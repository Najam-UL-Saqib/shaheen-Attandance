## 2. Hard-coded settings moved to the Settings tab

### New setting: **Max consecutive periods per teacher**

- Stored in `school_settings.max_consecutive_periods` (default `3`).
- Migration: **`supabase/migrations/20260902190944_configurable_consecutive_limit.sql`** — must be applied (see §4).
- Edited on **Settings → Weekly schedule**.
- Consumed by:
  - `src/routes/timetable.tsx` — cell save validation, conflict list, and the **Auto-generate** algorithm
  - `src/routes/day-view.tsx` — substitution save validation and the "consecutive periods" cell highlighting
- All previously hard-coded `3` / `4` strings now interpolate the live value.
- Falls back to `3` (the `MAX_CONSECUTIVE_TEACHING_PERIODS` constant) while settings load or if the migration has not been applied yet.

### Already configurable (unchanged)

`working_days`, `periods_per_day`, `break_after_period` — already on the Settings tab. The fallback
constants (`DEFAULT_WORKING_DAYS`, `DEFAULT_PERIODS_PER_DAY`, `DEFAULT_BREAK_AFTER_PERIOD`) now live
together in `src/lib/schedule.ts` instead of being inline literals.

### Not settings (left as-is)

Theme colours (already user-configurable via `Settings → Appearance`, stored per-browser),
day names, UI spacing / colours.

### Bugs fixed while wiring the new setting

`src/routes/settings.tsx` mishandled the `["settings"]` query lifecycle two ways, both able to
**silently persist wrong values** for `working_days` / `periods_per_day` / `break_after_period` /
`max_consecutive_periods` (one `save()` writes all four):

1. It re-seeded every field from `data` on **every** `data` change — a refetch mid-edit (window
   focus, post-save invalidation) reverted unsaved edits. Now seeded once via a `seeded` ref.
2. Nothing stopped a `save()` before the row had loaded, so it wrote the `useState` defaults
   (`break_after_period: 0`, etc.). Now the Save buttons are `disabled={!data}` and `save()` early-returns
   when `data` is undefined.

Both caught by the Playwright settings-persistence test.

## 3. Reports — Table A rework

### Table A — *Class/Section × Subject* (final layout)

- **One number per cell** — the weekly periods assigned for that subject (teacher name and the
  `allocated / used` pair moved to a hover tooltip). A red number means the timetable count ≠ the
  allocation.
- **First column** — `<class> – <section>` with the **class teacher name inline** on the same line
  (small, no label).
- **Games** column — count of game / PT periods for the section.
- **Total** column — a single number: the section's assigned subject periods (games excluded).
- Compact: `table-fixed`, short horizontal subject headers (`Eng`, `Gen Sci`, … full name on hover),
  tight one-line rows — no horizontal scroll, the whole 24-row table fits one screen.

### Export PDF

- **Export PDF** button in the Reports header → `window.print()`.
- `@media print` rules in `src/styles.css` drop the sidebar, tabs, and the button, expand the table
  to the page, and force `A4 landscape`. Prints whichever tab is open. Elements tagged `.no-print`
  are hidden; the report card is tagged `.print-area`.

### Table B — *Teacher × Class/Section*

- Same compact single-number treatment: each cell is the periods the teacher is assigned in that
  class/section (allocated vs timetable on hover, red on mismatch). Compact `1A`…`12B` headers,
  `table-fixed`, one-line rows — the whole 29-teacher matrix fits one screen / one landscape page.
- **Total** — the teacher's whole-week workload as a single number.

### Timetable double-booking is now hard-blocked

- **Migration `20260904080901`** — `unique index (teacher_id, day, period)` on `timetable_slots`.
  A teacher can no longer be in two class/sections in the same weekly period, at the database level.
  (Two lessons in one class period was already blocked by `unique (section_id, day, period)`.)
- **Timetable editor** — the teacher-clash check is now a hard stop (`toast.error`, no "Save anyway"),
  with a plain-language message; the DB error is also translated. Room clashes stay a soft confirm.
- **Day View** — same: substituting a teacher who is already teaching elsewhere in that period on
  that date is refused outright.
- E2E (`e2e/timetable.spec.ts`) hits the REST API as the admin and asserts both inserts return `409`.

### Teacher deletion guard

Deleting a teacher used to hard-cascade — every `teacher_allocation`, `teacher_allocation_subject`
and `timetable_slot` for them was removed with only a confirm dialog, silently punching holes in the
timetable and the reports. The Teachers page now:

- shows a **Workload** column (`N sections · P/wk`, plus a *Class teacher* badge);
- **blocks the delete** with a specific message when the teacher still has allocations, timetable
  lessons, or a class-teacher role — "Reassign on the Workload Allocation, Timetable and Classes &
  Sections pages first";
- only deletes when the teacher is clean (dims the trash icon otherwise).

### Why some cells are still `—` (not a bug)

- **Table A** `—` = the subject is **not in that class's curriculum** (e.g. grade 3 has no Physics).
  There is no teacher or period to show. Every cell that *should* have data shows `N / N`.
- **Table B** `—` = that teacher is **not assigned to that section**. A real teacher only teaches
  5–6 sections, so the teacher×section grid is inherently ~75% empty. It cannot be filled without a
  teacher covering all 24 sections (100+ periods/week), which is impossible. Fewer teachers make it
  denser but never full.

## 7. Post-demo client requirements (v2)

Full analysis: `docs/timetable-v2-plan.html`. The 9 requests are grouped into phases; each phase is a
commit.

### Phase 1 — Day View (R2, R3, R5, R6) — done

- **R3 — teacher names in Reports** already shipped in §3; added a *Hide/Show teacher names* toggle so
  Table A can still collapse to a single number per cell.
- **R6 — cover for a missing teacher**: the Day-View cell editor now lists *teachers with no class this
  period, allocated to this section* first, with a *Show all available* button to widen the list to
  every free teacher.
- **R2 — emergency consecutive periods**: exceeding the consecutive-period limit in Day View is now a
  confirm ("Assign anyway (emergency cover)?"), not a hard block. The weekly Timetable editor still
  blocks it. Teacher double-booking stays a hard block everywhere.
- **R5 — teacher leaves for the day**: *Teacher away* button — pick the teacher and the period they
  leave after; every later lesson that day is listed for reassignment (to a free teacher or "no
  teacher / free period"). Weekly timetable untouched; changes are per-date `timetable_day_overrides`.

### Phase 2a — Per-class breaks (R7) — done

- New tables `breaks` + `break_classes`. A break has a name and an "after period N" position and
  applies to the classes you attach to it.
- **Settings → Breaks card**: create/edit named breaks, tick the classes each covers; the old single
  school-wide "break after period" is now the *default* used by any class with no custom break.
- Timetable and Day View render each class's own break column(s).
- `src/lib/breaks.ts` (`breakPositionsForClass`, `allBreakPositions`) + unit tests.

### Phase 2b — Combined classes & elective blocks (R1, R4) — done

- **R1 — combined class**: in the Timetable cell editor, *Combined* mode — one teacher/subject/room
  taught to this section **plus** other sections of the same class in one slot (e.g. 9-A + 9-B
  together for Computer). Stored as one row per section sharing a `group_id`, `group_kind='combined'`.
- **R4 — elective block**: *Elective* mode — this section splits, several subjects run in parallel
  with different teachers (e.g. Biology / Computer). Stored as N rows for the one section sharing a
  `group_id`, `group_kind='elective'`.
- DB: partial unique indexes let combined lessons repeat a teacher across sections and elective blocks
  repeat a section across subjects, while every ordinary lesson keeps the one-teacher / one-section
  per-period guarantee (`20260904125307_group_kind_and_indexes.sql`). `group_id` is a plain grouping
  uuid — the parent `teaching_groups` table was dropped as redundant
  (`20260904160000_drop_teaching_groups_fk.sql`).
- Auto-generate leaves combined/elective cells untouched and fills around them.
